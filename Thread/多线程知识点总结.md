## 1. 继承 Thread

**是什么：** 自己写一个类，继承 `java.lang.Thread`，重写 `run()` 方法，然后调用 `start()` 启动线程。

**为什么需要：** Java 程序默认只有 main 线程（单线程），想让多个任务同时执行，就需要创建新线程。

**怎么用：**

```java
// 步骤1：继承 Thread
class PrintOdd extends Thread {
    @Override
    public void run() {
        // 线程要执行的代码写在这里
        for (int i = 1; i <= 10; i += 2) {
            System.out.println(Thread.currentThread().getName() + " 打印奇数: " + i);
        }
    }
}

// 步骤2：创建对象 + 调用 start()
public class Main {
    public static void main(String[] args) {
        PrintOdd t1 = new PrintOdd();    // 创建线程对象
        t1.start();                      // 启动线程（JVM 会调用 run()）
    }
}
```

**注意：** 必须调 `start()` 而不是 `run()`。直接调 `run()` 就是普通方法调用，不会新开线程。

## 2. 实现 Runnable

**是什么：** 自己写一个类，实现 `Runnable` 接口，重写 `run()` 方法。然后把对象传给 `Thread` 构造函数。

**为什么需要：**
- Java 单继承，继承了 Thread 就不能继承别的类了
- Runnable 把"任务"和"线程"解耦，多个线程可以共享同一个任务对象

**怎么用：**

```java
// 步骤1：实现 Runnable（这是"任务"）
class TicketRunnable implements Runnable {
    private int tickets = 10;

    @Override
    public void run() {
        while (true) {
            if (tickets > 0) {
                System.out.println(Thread.currentThread().getName() + " 卖出第" + tickets + "张票");
                tickets--;
            } else {
                break;
            }
        }
    }
}

// 步骤2：创建任务对象 + 包装成 Thread + 启动
public class Main {
    public static void main(String[] args) {
        TicketRunnable task = new TicketRunnable();   // 一个任务

        Thread t1 = new Thread(task, "窗口1");         // 三个线程共享一个任务
        Thread t2 = new Thread(task, "窗口2");
        Thread t3 = new Thread(task, "窗口3");

        t1.start();
        t2.start();
        t3.start();
    }
}
```

**Thread vs Runnable 对比：**

| | Thread 继承 | Runnable 实现 |
|---|-----------|-------------|
| 写法 | `class A extends Thread` | `class A implements Runnable` |
| 继承 | 不能再继承别的类 | 还可以继承别的类 |
| 资源共享 | 通常用 static 变量共享 | 同一 Runnable 对象变量自然共享 |
| 耦合度 | 任务和线程绑死 | 任务和线程分离，更灵活 |

## 3. 线程安全 — synchronized

**是什么：** 给代码块或方法加一把"锁"，同一时刻只有一个线程能执行被锁住的代码。

**为什么需要：** 多个线程同时修改同一个变量（如 `tickets--`），会出现数据错乱。例如：
- 线程A读到 tickets=5
- 线程B也读到 tickets=5
- 两个都卖出"第5张"，实际少卖一张

**怎么用：**

```java
// 方式1：同步代码块（锁住 this）
public void run() {
    while (true) {
        synchronized (this) {                    // 拿到锁才能进
            if (tickets > 0) {
                System.out.println(Thread.currentThread().getName()
                        + " 卖出第" + tickets + "张票");
                tickets--;
            } else {
                break;
            }
        }                                        // 出代码块自动释放锁
    }
}

// 方式2：同步方法
public synchronized void sellTicket() {           // 锁住整个方法
    if (tickets > 0) {
        System.out.println("卖出第" + tickets + "张票");
        tickets--;
    }
}

// 方式3：同步代码块（锁住任意对象）
private Object lock = new Object();
synchronized (lock) { ... }
```

**关键理解：**
- `synchronized (obj)` —— obj 是锁对象，线程进入前必须先拿到它
- 同一个锁对象，同一时刻只能被一个线程持有
- 出了 `synchronized` 块，锁自动释放

## 4. 线程安全 — ReentrantLock

**是什么：** `java.util.concurrent.locks.ReentrantLock`，一把"显式"的锁，需要手动 `lock()` 和 `unlock()`。

**为什么需要：** synchronized 功能比较简单，ReentrantLock 更灵活——可以尝试获取锁（tryLock）、可以中断等待、可以设置公平锁。

**怎么用：**

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class TicketRunnable implements Runnable {
    private int tickets = 10;
    private Lock lock = new ReentrantLock();    // 创建锁对象

    @Override
    public void run() {
        while (true) {
            lock.lock();                         // 加锁
            try {
                if (tickets > 0) {
                    System.out.println(Thread.currentThread().getName()
                            + " 卖出第" + tickets + "张票");
                    tickets--;
                } else {
                    break;
                }
            } finally {
                lock.unlock();                   // 必须放在 finally 里释放！
            }
        }
    }
}
```

**synchronized vs ReentrantLock：**

| | synchronized | ReentrantLock |
|---|-------------|--------------|
| 加锁/释放 | 自动 | 手动 `lock()` / `unlock()` |
| 释放保证 | JVM 保证 | 必须 `finally { unlock() }` |
| 公平锁 | 不支持 | 支持 `new ReentrantLock(true)` |
| 尝试获取锁 | 不支持 | 支持 `tryLock()` |
| 性能 | 低竞争时好 | 高竞争时好 |

## 5. 线程安全 — AtomicInteger（乐观锁）

**是什么：** `java.util.concurrent.atomic.AtomicInteger`，用 CAS（Compare And Swap）实现的原子整数。**不加锁**也能保证线程安全。

**为什么需要（CAS 原理）：**

线程不是先加锁再操作，而是直接修改，CPU 硬件保证"比较并交换"这一步不可分割：

```
CAS(期望值A, 新值B):
  如果内存当前值 == A：
      改成 B，成功
  否则：
      被别人改过了，失败，重试
```

Java 已经把 CAS 包装好了（AtomicInteger），直接用就行。

**怎么用：**

```java
import java.util.concurrent.atomic.AtomicInteger;

class TicketRunnable implements Runnable {
    private AtomicInteger tickets = new AtomicInteger(10);   // 原子整数

    @Override
    public void run() {
        while (true) {
            int ticketNum = tickets.getAndDecrement();  // 原子操作：先取值再减1
            if (ticketNum <= 0) {
                System.out.println(Thread.currentThread().getName() + " 票卖完了");
                break;
            }
            System.out.println(Thread.currentThread().getName()
                    + " 卖出第" + ticketNum + "张票");
        }
    }
}
```

**AtomicInteger 常用方法：**

| 方法 | 说明 | 示例（初始值=10） |
|------|------|------------------|
| `get()` | 读取当前值 | 返回 10 |
| `getAndDecrement()` | 先取值再减1 | 返回 10，值变成 9 |
| `decrementAndGet()` | 先减1再取值 | 值变成 9，返回 9 |
| `getAndIncrement()` | 先取值再加1 | 返回 10，值变成 11 |
| `incrementAndGet()` | 先加1再取值 | 值变成 11，返回 11 |
| `compareAndSet(A, B)` | 如果值是A就改成B | CAS 原始方法 |
| `addAndGet(n)` | 加 n 再取值 | 如 `addAndGet(5)` 返回 15 |

## 6. 线程通信 — wait / notify

**是什么：** `Object` 类的方法，让线程之间可以"对话"——一个线程等待，另一个线程喊它醒来。

**为什么需要：** 比如交替打印奇偶数——奇数线程打印完了要通知偶数线程"该你了"，自己等着；偶数线程打完再通知奇数线程。

**怎么用：**

```java
/**
 * 两个线程交替打印 1~100
 */
public class AlternatePrint {
    private int number = 1;

    // 打印奇数
    public synchronized void printOdd() {
        while (number <= 100) {
            if (number % 2 == 0) {              // 当前是偶数，不该我打印
                try {
                    wait();                     // 释放锁，进入等待
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
            System.out.println(Thread.currentThread().getName()
                    + " -> " + number);
            number++;
            notify();                           // 唤醒对方线程
        }
    }

    // 打印偶数
    public synchronized void printEven() {
        while (number <= 100) {
            if (number % 2 == 1) {              // 当前是奇数，不该我打印
                try {
                    wait();                     // 释放锁，进入等待
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
            System.out.println(Thread.currentThread().getName()
                    + " -> " + number);
            number++;
            notify();                           // 唤醒对方线程
        }
    }
}

// 调用方式
public class Main {
    public static void main(String[] args) {
        AlternatePrint ap = new AlternatePrint();
        new Thread(() -> ap.printOdd(), "奇数线程").start();
        new Thread(() -> ap.printEven(), "偶数线程").start();
    }
}
```

**三个方法对比：**

| 方法 | 作用 | 注意 |
|------|------|------|
| `wait()` | 当前线程释放锁，进入等待状态 | 必须在 `synchronized` 里调用 |
| `notify()` | 随机唤醒**一个**正在 wait 的线程 | 必须在 `synchronized` 里调用 |
| `notifyAll()` | 唤醒**所有**正在 wait 的线程 | 必须在 `synchronized` 里调用 |

## 7. Callable + FutureTask

**是什么：** `Callable<T>` 是一个接口，和 Runnable 很像，但 `call()` 方法**有返回值**，可以**抛异常**。`FutureTask` 是"包装器"，把 Callable 包装成 Runnable，然后传给 Thread。

**为什么需要：** Runnable 的 `run()` 没有返回值，很多时候你希望线程执行完给你一个结果（比如计算结果）。

**怎么用：**

```java
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.FutureTask;

public class CallableDemo {
    public static void main(String[] args) throws ExecutionException, InterruptedException {

        // 步骤1：创建 Callable 任务
        Callable<Integer> task1 = new Callable<Integer>() {
            @Override
            public Integer call() throws Exception {
                int sum = 0;
                for (int i = 1; i <= 50; i++) {
                    sum += i;
                }
                return sum;    // 有返回值！
            }
        };

        Callable<Integer> task2 = new Callable<Integer>() {
            @Override
            public Integer call() throws Exception {
                int sum = 0;
                for (int i = 1; i <= 100; i++) {
                    sum += i;
                }
                return sum;
            }
        };

        // 步骤2：用 FutureTask 包装 Callable
        FutureTask<Integer> ft1 = new FutureTask<>(task1);
        FutureTask<Integer> ft2 = new FutureTask<>(task2);

        // 步骤3：传给 Thread 并启动
        Thread t1 = new Thread(ft1);
        Thread t2 = new Thread(ft2);
        t1.start();
        t2.start();

        // 步骤4：通过 FutureTask.get() 获取返回值（阻塞等待）
        Integer result1 = ft1.get();
        Integer result2 = ft2.get();

        System.out.println("任务1结果（1+...+50）: " + result1);
        System.out.println("任务2结果（1+...+100）: " + result2);
    }
}
```

**三个角色的关系：**

```
Callable<T>      →  "有返回值的任务"（定义要做什么，返回什么）
    ↓ 包装
FutureTask<T>    →  "有结果的凭据"（实现了 Runnable，能传给 Thread）
    ↓ 拿到
ft.get()         →  阻塞等待线程结束，返回结果
```

**Runnable vs Callable 对比：**

| | Runnable | Callable |
|---|----------|----------|
| 方法 | `void run()` | `T call() throws Exception` |
| 返回值 | 无 | 有（泛型 T） |
| 异常 | 不能抛受检异常 | 可以抛 `throws Exception` |
| 提交方式 | `new Thread(task)` | 先 `FutureTask(task)` 再 `new Thread(ft)` |
| 拿结果 | 没法拿 | `FutureTask.get()` |

## 8. 线程池 — ExecutorService

**是什么：** 预先创建好一批线程放在"池子"里，有任务来就分配空闲线程执行，执行完线程不销毁，回到池里等下一个任务。

**为什么需要：** 频繁创建和销毁线程开销很大。线程池复用线程，避免反复创建销毁。

**类比：** 餐馆固定雇 3 个厨师（线程池的 3 个线程），来 100 桌客人（任务）就排队，每人做完一桌接下一桌，不是来一桌就招一个厨师。

**怎么用：**

```java
import java.util.concurrent.*;

public class ThreadPoolDemo {
    public static void main(String[] args) throws ExecutionException, InterruptedException {

        // 1. 创建固定大小的线程池（3 个线程）
        ExecutorService pool = Executors.newFixedThreadPool(3);

        // 2. 提交 Runnable 任务（无返回值）
        for (int i = 1; i <= 5; i++) {
            pool.submit(new Runnable() {
                @Override
                public void run() {
                    int sum = 0;
                    for (int j = 1; j <= 100; j++) {
                        sum += j;
                    }
                    System.out.println(Thread.currentThread().getName()
                            + " 计算 1~100 的和 = " + sum);
                }
            });
        }

        // 3. 提交 Callable 任务（有返回值）
        Future<Integer> future1 = pool.submit(new Callable<Integer>() {
            @Override
            public Integer call() throws Exception {
                int sum = 0;
                for (int j = 1; j <= 100; j++) {
                    sum += j;
                }
                return sum;
            }
        });

        Future<Integer> future2 = pool.submit(new Callable<Integer>() {
            @Override
            public Integer call() throws Exception {
                int sum = 0;
                for (int j = 1; j <= 100; j++) {
                    sum += j;
                }
                return sum;
            }
        });

        // 4. 通过 Future.get() 取 Callable 返回值（阻塞等待）
        System.out.println("Callable1 结果: " + future1.get());
        System.out.println("Callable2 结果: " + future2.get());

        // 5. 关闭线程池（不接新任务，已有任务跑完就关）
        pool.shutdown();
    }
}
```

**线程池执行流程（3个线程，5个任务）：**

```
任务1 ──→ 线程1（空闲）    同时执行
任务2 ──→ 线程2（空闲）    同时执行
任务3 ──→ 线程3（空闲）    同时执行
任务4 ──→ 排队，等空闲线程
任务5 ──→ 排队，等空闲线程
```

**常用方法：**

| 方法 | 作用 |
|------|------|
| `Executors.newFixedThreadPool(n)` | 创建固定 n 个线程的池子 |
| `pool.submit(Runnable)` | 提交无返回值的任务 |
| `pool.submit(Callable)` | 提交有返回值的任务，返回 `Future<T>` |
| `Future.get()` | 阻塞等待任务结束，拿到返回值 |
| `pool.shutdown()` | 不再接新任务，等已有任务跑完关闭 |
| `pool.shutdownNow()` | 立即关闭，尝试中断正在跑的任务 |

## 9. 悲观锁 vs 乐观锁

| 对比维度 | 悲观锁 | 乐观锁 |
|---------|--------|--------|
| **核心思路** | "肯定有人跟我抢，先锁上" | "大概率没人抢，先改了再说" |
| **实现方式** | `synchronized`、`ReentrantLock` | CAS（AtomicInteger 等） |
| **线程状态** | 没拿到锁的线程**阻塞**，进入等待队列 | **不阻塞**，自旋重试 |
| **上下文切换** | 有（线程休眠/唤醒） | 无 |
| **适合场景** | 竞争激烈（写多） | 竞争不激烈（读多写少） |
| **Java 类** | `synchronized`、`Lock` | `AtomicInteger`、`AtomicLong`、`AtomicReference` |

**关键区别一图看懂：**

```java
// 悲观锁：先抢锁，再操作
lock.lock();
try {
    if (tickets > 0) {
        tickets--;                  // 有锁保护，放心改
    }
} finally {
    lock.unlock();
}

// 乐观锁：直接操作，硬件保证原子性
int n = tickets.getAndDecrement();  // 整个"读+改"原子完成，不加锁
if (n <= 0) break;
```

## 10. start() 和 run() 的区别

| | `start()` | `run()` |
|---|----------|---------|
| 调用者 | 你调用 | JVM 调用 |
| 效果 | 启动**新线程**，在新线程里执行 run() | **不新开线程**，在当前线程里执行 |
| 只能调几次 | 一个线程对象只能调一次 start() | 可以反复调（就是普通方法） |

```java
Thread t = new Thread(new MyRunnable());

t.start();   // ✅ 新线程，run() 在新线程里跑
t.run();     // ❌ 普通方法调用，还是在 main 线程里跑，没用上多线程
```

## 11. 常用线程方法

| 方法 | 说明 |
|------|------|
| `Thread.currentThread()` | 获取当前正在执行的线程对象（静态方法） |
| `Thread.currentThread().getName()` | 获取当前线程名 |
| `thread.setName("名字")` | 设置线程名 |
| `new Thread(task, "名字")` | 构造时指定名字 |
| `Thread.sleep(毫秒)` | 当前线程休眠（静态方法） |
| `thread.join()` | 等待该线程执行结束，再继续往下走 |
| `thread.setPriority(n)` | 设置优先级（1~10，默认 5） |
| `thread.isAlive()` | 判断线程是否还活着 |

## 完整知识地图

```
多线程
├── 创建线程
│   ├── 继承 Thread（extends Thread + start()）
│   └── 实现 Runnable（implements Runnable + new Thread(task)）
│
├── 线程安全
│   ├── 悲观锁
│   │   ├── synchronized（自动加锁/释放）
│   │   └── ReentrantLock（手动 lock()/unlock()）
│   └── 乐观锁
│       └── AtomicInteger（CAS 原子操作，不加锁）
│
├── 线程通信
│   └── wait() / notify() / notifyAll()
│
├── 有返回值的任务
│   ├── Callable<T>（call() 方法有返回值）
│   └── FutureTask<T>（包装 Callable 成 Runnable）
│
└── 线程池
    ├── ExecutorService（线程复用，不要反复创建）
    ├── pool.submit(Runnable)
    ├── pool.submit(Callable) → Future<T>
    └── pool.shutdown()
```
